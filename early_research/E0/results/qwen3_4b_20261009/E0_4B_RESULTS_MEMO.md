# E0-scale 结果：Qwen3-4B 与单分片降精度

- **运行**：2026-10-09 至 10-10。设计见 [E0_EXPERIMENT_DESIGN.md §5](../../docs/E0_EXPERIMENT_DESIGN.md)。0.6B 的对照结果见 [E0_RESULTS_MEMO](../full_20261009/E0_RESULTS_MEMO.md)。
- **规模**：33,280 个 context（520 个 prompt × 64 个位置），共 30 个执行栈。
  - CUDA 服务器上 24 个：参考是 CPU fp32，另有 CUDA torch 和 mlx-CUDA；
  - Apple M4 节点上 6 个：Apple MPS 和 mlx-Metal。
- **产物**：
  - 自动报告：[spec_bf16](analysis/spec_bf16/E0_REPORT.md) · [spec_8bit](analysis/spec_8bit/E0_REPORT.md) · [spec_8bit_nobnb](analysis/spec_8bit_nobnb/E0_REPORT.md)
  - 失配率与误差尺度汇总：[e0_error_scale_and_rates.txt](e0_error_scale_and_rates.txt)
  - 摘要清单：[MANIFEST.sha256](MANIFEST.sha256)；原始 npz 在 CUDA 服务器的 `~/qfc_e0/qwen3_4b_20261009/captures/`。
- **N 的含义**：要求误报和漏报都不超过 10⁻³ 时，所需 canary 个数的精确二项设计。canary 区间在偶数 prompt 上挑选、在奇数 prompt 上报告；诚实失配率用 Wilson 95% 上界。"—"表示在 N≤20000 内无法区分。

## 0. 结论

1. **0.6B 高估了信号。** 从 0.6B 到 4B，各种 4-bit 的失配率下降 40–50%，误差窗口（作弊误差 / bf16 诚实误差）从 6–24 倍缩到 5–11 倍。
2. **诚实漂移的结构是稳定的。** 4B 上，bf16、fp16、mlx-8bit 在 CUDA 和 Apple 之间的失配仍然几乎全部是平局造成的。只看参考 margin ≥ 0.5 的位置（占 83%），失配约为 0。
3. **能不能检测，取决于"允许诚实节点用哪些实现"。** 把 bnb LLM.int8 算作合法的 8-bit 实现时（它在高 margin 区的失配率为 0.59%，是其他诚实栈的几十倍），**单分片 GPTQ-4 即使不考虑升级攻击也完全检测不出来**。去掉它之后，所有作弊方式在不升级时都能用 N ≤ 462 个 canary 检出。
4. **最难的组合是"尾分片 + GPTQ"。** 尾分片能看到最终 logits，所以能做升级攻击。在规格 8-bit（不含 bnb）的设定下，升级 10% 就让所需 canary 数从 421 涨到 7033，预注册判据为 True。在流水线里，这是最现实、也最强的作弊者。
5. **对 QFC 的含义：主动信号的动机在"大模型 + 单分片 + 强量化器"这个区间成立了**（0.6B 上没有成立）。但窗口只有 2.6–4.4 倍，信号该怎么设计必须在这个窗口里推导。

## 1. 失配率与误差尺度（相对 CPU fp32）

| 栈 | 失配率 | 参考 margin ≥ 0.5 时的失配率 | logit 误差中位数 | 相对 bf16 |
|---|---|---|---|---|
| bf16（CUDA / MPS / mlx-CUDA / mlx-Metal） | 1.29–1.42% | 0 | 0.056–0.057 | 1× |
| fp16（CUDA / MPS） | 0.16–0.17% | 0 | 0.007 | 0.13× |
| 8-bit（RTN / mlx-Metal） | 1.67–1.84% | 0.01% | 0.070–0.078 | 1.3× |
| bnb LLM.int8 | 4.07% | **0.59%** | 0.195 | 3.4× |
| 整模型 RTN-4 / mlx-4 / MPS-RTN-4 / NF4 | 11.4–13.3% | 5.2–6.4% | 0.53–0.65 | 9–11× |
| 整模型 GPTQ-4 | 6.27% | 1.81% | 0.30 | 5.3× |
| 单分片 RTN-4（各占 1/3） | 7.1–8.3% | 1.9–2.8% | 0.34–0.41 | 6–7× |
| 单分片 mlx-4（EXO 的 kernel） | 6.3–7.2% | 1.4–2.1% | 0.28–0.37 | 5–6.5× |
| **单分片 GPTQ-4** | **3.4–4.1%** | **0.43–0.68%** | **0.15–0.25** | **2.6–4.4×** |

对照 0.6B：整模型 RTN-4 的失配率是 21.7%，GPTQ-4 是 10.8%；bf16 的 logit 误差中位数是 0.049。

## 2. 所需 canary 数 N（无升级 → 升级 10%）

| 作弊栈 | spec_bf16 | spec_8bit（含 bnb） | spec_8bit（不含 bnb） |
|---|---|---|---|
| 整模型 RTN-4 / mlx-4 | 26–31 → 48–66 | 81–120 → 289–471 | 31–36 → 63–82 |
| 整模型 GPTQ-4 | 82 → 243 | 1362 → — | 104 → 348 |
| 单分片 RTN-4 | 48–69 → 139–182 | 294–547 → 2969–— | 63–78 → 170–263 |
| 单分片 mlx-4 | 68–90 → 165–280 | 528–1513 → — | 77–113 → 247–377 |
| **单分片 GPTQ-4** | **175–325 → 733–1972** | **— → —** | **233–462 → 1318–7033** |
| 8-bit（spec_bf16 下算作弊） | mlx 5997–15313，RTN 检不出 | — | — |

**解读：**
- 升级攻击只有**尾分片**（层 24–35）能做，因为只有它看得到最终 logits。对头分片和中间分片来说，"无升级"那一列就是现实的检测强度。
- 尾分片 GPTQ 是全表最难的一项：spec_8bit（不含 bnb）下从 421 涨到 7033；spec_bf16 下从 315 涨到 1972。
- 8-bit 冒充 bf16：和 0.6B 一样基本检不出。窗口只有 1.3 倍。

## 3. 和 0.6B 结论的对照

| 结论 | 0.6B | 4B |
|---|---|---|
| 诚实失配集中在平局附近，可以过滤掉 | 成立 | **成立** |
| 被动 canary 能检出整模型 4-bit | 成立（N=29–133） | **成立**（N=26–104，不含 bnb） |
| 朴素升级攻击打不穿被动方法 | 对整模型成立 | 对整模型成立；**对尾分片 GPTQ 不成立** |
| 误差窗口（作弊 / bf16） | 6–24× | **5–11×（整模型），2.6–4.4×（单分片 GPTQ）** |

## 4. 已知问题

- **合法实现集合必须写进规格。** bnb LLM.int8 一个栈就决定了 spec_8bit 的结论。论文里要么把诚实实现限定在"按组 affine 的 8-bit"（例如 mlx、RTN），要么把 bnb 单独作为一种场景报告。
- fp32 参考是在 CPU 上算的（GPU 是共享的，放不下）。0.6B 的参考是 CUDA fp32。两者都是 fp32，0.6B 上 CUDA 与 MPS 的 fp32 top-1 完全一致，因此不影响结论。
- 单分片的升级攻击默认攻击者看得到 logit margin，这对非尾分片过于宽松（偏保守）。
- mlx-CUDA 第一次运行时因共享 GPU 显存不足而失败，关闭 mlx 的缓冲区缓存（`set_cache_limit(0)`）后重跑成功。
- GPTQ 仍是紧凑实现（无 act-order）；AWQ 未覆盖。生产级的量化器只会让窗口更窄。
