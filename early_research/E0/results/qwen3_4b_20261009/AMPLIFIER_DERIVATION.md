# 公开放大器能省多少请求：推导与基于 4B 数据的估计

- **日期**：2026-10-10
- **脚本**：[`e0_amplifier_model.py`](../../scripts/e0_amplifier_model.py)
- **完整输出**：[analysis/amplifier/AMPLIFIER_REPORT.md](analysis/amplifier/AMPLIFIER_REPORT.md)、`amplifier_model.json`
- **数据**：E0-scale（Qwen3-4B）每个 context 实测的误差。
- **N 的口径**：要求误报和漏报都 ≤10⁻³ 时，精确二项设计给出的最少 token 数；按每个请求 64 个 token 换算成请求数。

## 1. 模型

**放大器（全部公开）**
- 每个输出位置计算一个标量 `s = ⟨k, h⟩`，h 是末层隐状态；
- 读出一位 `b = sign(sin(ω·s))`；
- 用 logit 偏置让输出 token 落在 b 指定的那半个词表；
- 验证方用全精度参考模型，沿 provider 返回的 token 序列重算，得到每个位置正确的 b₀。

**误差**
- 执行栈实际算出的是 `s + e`。诚实栈的误差尺度记为 σ_h，作弊栈记为 σ_q = ρ·σ_h。
- 相位 `φ = ω·s mod 2π` 视为均匀分布。
- 读出位翻转，当且仅当误差 ω·e 把相位推过了 sin 的零点。记 x = ω·σ_h，单个位置的翻转概率为

  ```
  p(x) = E[ tri(x·Z) ]，tri(δ) = δ 到最近 2π 整数倍的距离 / π
  ```

  - x 很小时：`p ≈ x·E|Z|/π`（高斯情况下约为 0.254x）；
  - x 很大时：p 趋于 1/2，读出位完全随机。

**输出信道**
- token 只以概率 1−η 落在 b 指定的半区，η 由偏置强度和文本熵决定；
- 观测到的失配率为 `p' = η + (1−2η)·p`。
- 低熵位置无论偏置如何都会输出同一个 token，对检测没有贡献。η 实际上是这类位置和偏置强度共同决定的。

**检测**
- 区分诚实失配率 p'_h 和作弊失配率 p'_q，所需 token 数约为 `N ≈ ln(1/α) / KL(p'_q ‖ p'_h)`；实际数字用精确二项设计算。
- ω 由验证方事先选定，取让 N 最小的值。

**升级攻击（只有尾分片能做）**
- 攻击者知道自己算出的相位 `φ' = φ + ω·e_q`，把离零点最近的 c 比例位置改用规格精度重算。

**半实证部分的误差来源**
- e 直接取 E0-4B 中同一 context 上"参考 top-1/top-2 logit 差"的实测偏差，带有真实的重尾。
- 这里假设读出 s 和 logit 差一样，都是末层隐状态的线性泛函，因此误差形状相同。

## 2. 解析结果（高斯误差，无升级）

| ρ = σ_q/σ_h | η=0 | η=0.1 | η=0.2 | η=0.3 | 最优 x | p_h / p_q（η=0） |
|---|---|---|---|---|---|---|
| 1.3（8-bit 冒充 bf16） | 1431 | 2341 | 4301 | 9833 | 1.16 | 0.29 / 0.37 |
| 2.0 | 230 | 383 | 699 | 1593 | 0.87 | 0.22 / 0.41 |
| **3.0（单分片 GPTQ 量级）** | **105** | 178 | 328 | 756 | 0.65 | 0.17 / 0.44 |
| 4.4 | 67 | 113 | 216 | 514 | 0.46 | 0.12 / 0.45 |
| 10（整模型 RTN 量级） | 35 | 71 | 139 | 323 | 0.23 | 0.06 / 0.47 |

**解读：**
- 最优的放大倍数大约让作弊者的相位误差达到 1–2 弧度，也就是作弊者的读出位接近随机，同时诚实节点的翻转率控制在 10–30%。
- 所需 token 数主要取决于 ρ 和 η。η 从 0 增大到 0.3，代价会放大 5–9 倍。

## 3. 半实证结果：请求数，放大器 vs 被动

被动方法用 E0 实测的最佳区间。它只能利用参考 margin 落在该区间内的位置，大约占全部位置的 10%。放大器每个 token 都能用。

**spec_bf16**（诚实栈：bf16 和 fp16，CUDA 与 Apple）：

| 作弊栈 | 升级 0% | 5% | 10% | 20% |
|---|---|---|---|---|
| 尾分片 GPTQ-4（L24–35） | 被动 50 / 放大器 9–20 | 122 / 10–23 | **309 / 11–26** | **2444 / 15–36** |
| 中间分片 GPTQ-4（L12–23） | 28 / 7–16 | 58 / 8–18 | 115 / 9–21 | 314 / 12–27 |
| 尾分片 mlx-4（L24–35） | 13 / 4–9 | 22 / 4–9 | 44 / 5–11 | 219 / 6–13 |
| 整模型 GPTQ-4 | 13 / 5–10 | 22 / 5–11 | 38 / 6–13 | 136 / 7–17 |
| 整模型 mlx-4 | 5 / 3–6 | 6 / 3–7 | 8 / 3–7 | 20 / 4–9 |

**spec_8bit**（不含 bnb；诚实栈另加 RTN-8 与 mlx-8bit）：

| 作弊栈 | 升级 0% | 10% | 20% |
|---|---|---|---|
| 尾分片 GPTQ-4 | 66 / 19–43 | **1099 / 27–62** | **检不出 / 40–93** |
| 中间分片 GPTQ-4 | 37 / 13–30 | 103 / 18–41 | 632 / 26–61 |
| 整模型 GPTQ-4 | 17 / 7–16 | 28 / 9–21 | 92 / 12–29 |

表中放大器的两个数分别对应 η=0.2 和 η=0.3。

## 4. 结论

1. **没有升级攻击时，节省有限，约 2–6 倍。** 而且这主要来自"每个 token 都能用"，而不是放大器提高了每个 token 的信息量。
   - 按 token 计，在 η=0.2 时放大器反而比被动方法多用 token（例如尾分片 GPTQ：528 vs 315）。
   - 对整模型 4-bit，两者差不多，被动方法本来就够用。
2. **面对升级攻击时，节省可达 1–2 个数量级以上，这是放大器真正的价值。**
   - 被动方法的翻转集中在少数低 margin 的位置，作弊者用自己的 margin 就能找到这些位置，定点重算即可。所以升级 10–20% 就能让被动方法的成本暴涨或彻底失效。
   - 放大器在每个位置均匀地制造临界点，作弊者自己的相位误差约有 1–2 弧度，基本看不出哪些位置会翻转。所以重算 20% 只让成本增加约 1.5–2 倍。
   - 最难的组合（尾分片 GPTQ，规格 8-bit，升级 20%）：被动方法检不出；放大器需要 40–93 个请求。
3. **公开放大器提供的不是"更强的信号"，而是"抗升级、抗定点重算的信号"。** 它的上限仍然受误差比 ρ 约束：ρ≈1.3（8-bit 冒充 bf16）时，需要约 70–150 个请求，可以检出但成本不低。

## 5. 这个估计的局限（按风险从高到低）

1. **η 和输出质量是一对此消彼长的量，目前还没测。** η 越小，需要的偏置越强，输出被扭曲得越厉害，类似于强水印对质量的损害。低熵位置不提供任何信息。η=0.2–0.3 是参照 Kirchenbauer 式水印的经验假设，需要实测。
2. **对诚实栈的校准很脆弱。** 放大器下诚实节点也有 12–22% 的位置会翻转，判定靠的是"约 19% 对约 38%"这种比例差。如果出现一个比校准时噪声更大的新诚实栈（比如新 kernel、新硬件），就可能被误判。被动方法在高 margin 区的诚实失配约为 0，对没见过的诚实栈要稳健得多。这是放大器的一个实打实的代价。
3. **只保住读出方向的攻击没有建模。** k 公开后，攻击者可以专门让 ⟨k,h⟩ 保持精确。需要让 k 随上下文从覆盖整个隐空间的大集合里选取，再做实验验证。
4. **误差形状的假设。** 读出的误差借用了 logit 差的实测误差分布；真正的读出方向需要在植入后实测。
5. **被动方法的请求数换算偏悲观。** 它的区间是按"token 数最少"挑的，而不是按"请求数最少"挑的。改为按请求数优化，被动方法的请求数可能下降几倍。但随升级比例暴涨的趋势不受影响。
6. **定位和验证成本。** 放大器读出依赖所有上游分片，只能检出、不能定位，定位仍要靠 TSTC 或重新编组。两种方法都需要验证方对每个被审计的回答做一次全精度前向。
