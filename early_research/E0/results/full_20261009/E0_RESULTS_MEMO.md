# E0 结果：被动 canary 基线与不确定性升级攻击

- **运行**：2026-10-09。设计见 [E0_EXPERIMENT_DESIGN.md](../../docs/E0_EXPERIMENT_DESIGN.md)。
- **规模**：33,280 个 context（520 个 evaluation prompt × 64 个续写位置），共 19 个执行栈。
  - 12 个在 CUDA 服务器上：torch 和 mlx；
  - 7 个在 Apple M4 节点上：MPS 和 mlx-Metal。
- **自动报告**：[spec_8bit](analysis/spec_8bit/E0_REPORT.md) · [spec_bf16](analysis/spec_bf16/E0_REPORT.md)；captures 和 contexts 的摘要见 [MANIFEST.sha256](MANIFEST.sha256)。原始 npz 留在 CUDA 服务器上：`~/qfc_e0/full_20261009/captures/`。

## 0. 结论

| 场景 | 被动 canary（不植入） | 朴素升级攻击（重算自身 margin 最小的 ≤10%） | 预注册判据 `motivation_holds` |
|---|---|---|---|
| **规格 8-bit（EXO 默认），作弊 4-bit** | **有效**：N = 29–133 | **打不穿**：N 最多放大约 3.4 倍（GPTQ：133 → 457；RTN：31 → 52） | **6 个作弊栈全部为 False** |
| 规格 bf16，作弊 8-bit | **基本无效**：mlx 8-bit 需要 N=4104，RTN-8 需要 8104 | 再升级就完全检不出 | True（但被动方法本来就不行） |
| 规格 bf16，作弊 4-bit | 有效：N = 16–35 | 打不穿：N ≤ 80 | 全部为 False |

**对 QFC 的含义：QFC 推导文档 §2 的核心动机在这个设定下被实验否定了。**

- 在 Qwen3-0.6B 上，4-bit 量化造成的 top-1 翻转大多发生在**量化模型自己也很自信**的位置：翻转处 margin 的中位数是 0.25–0.375，而 bf16 诚实翻转处是 0。
- 所以"margin 小就切回全精度"这种升级攻击花 10% 的成本，只能消掉一小部分翻转。
- 自然 prompt 加预存 top-1 的被动 canary，用几十到几百个 canary 就能检出 4-bit 作弊。
- 而 QFC 能工作的区间（窗口 ρ≈0.03，即规格 8-bit 或 bf16、作弊 4-bit）恰好就是被动方法已经能工作的区间。

## 1. 诚实漂移的结构（这是一个可以独立成立的发现）

| 栈 | 相对 fp32-CUDA 的 top-1 失配率 | 失配中自身 margin 恰好为 0 的比例 | 失配中参考 margin < 0.1 的比例 | 参考 margin ≥ 0.5 时的失配率 |
|---|---|---|---|---|
| `apple_mps_fp32` | **0.0000** | — | — | 0 |
| `torch_fp32_eager` | 0.0000 | — | — | 0 |
| `torch_fp16` / `apple_mps_fp16` | 0.0019 / 0.0022 | — | — | — |
| `torch_bf16` | 0.0179 | 0.83 | 0.91 | **0.0000** |
| `mlx_8bit`（EXO，CUDA） | 0.0249 | 0.63 | 0.73 | **0.0001** |
| `apple_mlx_8bit`（EXO，Metal） | 0.0276 | 0.62 | 0.71 | **0.0001** |
| `torch_rtn_w4g128` | 0.2174 | 0.09 | 0.16 | **0.1151** |
| `torch_gptq_w4g128` | 0.1076 | 0.16 | 0.26 | **0.0296** |
| `mlx_q4` | 0.1975 | 0.10 | 0.17 | **0.0960** |

- **跨硬件 fp32 完全一致**：NVIDIA CUDA 和 Apple MPS 之间 33,280 个 context 的 top-1 失配为 0。
- **诚实失配几乎全是平局**：bf16 和 8-bit 的失配集中在参考 margin 接近 0 的位置。bf16 的 logit 只有 8 位尾数，经常出现精确平局，只要平局打破的方式不同就会失配。
- **只取参考 margin ≥ 0.5 的 context**（占全部的 75.7%）：
  - 诚实失配降到约 10⁻⁴，包括 EXO 在 CUDA 和 Metal 上的 8-bit 路径；
  - 4-bit 作弊仍有 3–12% 的失配。
- **对比 [C1]（arXiv 2607.19490）**：它用各向同性高斯来模拟硬件噪声。真实的诚实漂移在 top-1 层面是高度结构化的（集中在平局附近），因此**很容易被过滤掉**。这对我们写 baseline 是有利证据。

## 2. 升级攻击为什么没打穿

以 spec_8bit 为例，攻击者升级时改用 `mlx_8bit`；表中 N 为精确二项设计，α=β=10⁻³。

| 作弊栈 | N（无升级） | N（升级 10%） | N（升级 20%） | N（升级 50%） |
|---|---|---|---|---|
| RTN-4 | 31 | 52 | 86 | 1908 |
| GPTQ-4 | 133 | 457 | 2117 | 检不出 |
| bnb NF4 | 47 | 89 | 219 | 8492 |
| mlx 4-bit（CUDA / Metal） | 35 / 35 | 66 / 64 | 133 / 130 | 3490 / 3226 |

- 升级攻击要真正生效，大约需要 20–50% 的全精度重算。作弊省下的成本因此被吃掉一大半。
- **误差补偿越好的量化器越难检**：GPTQ 的失配率只有 RTN 的一半，升级 20% 时 N 已经超过 2000。生产级量化器（AWQ、带 act-order 的 GPTQ、QuIP# 等）只会更难检。
- **这次测的攻击者是"弱"攻击者，只用自身 margin 决定是否升级。** 强攻击者的上界是：如果能准确预测哪些位置会翻转，只需重算等于失配率那么多的比例（GPTQ 为 10.8%，RTN 为 21.7%），残余失配就降到升级目标自身的水平。在"margin 规则"和"完美预测"之间，还有一个没测的区间：攻击者可以离线用全精度模型训练一个廉价的"翻转预测器"。这是被动方法真正的风险，见 §4 的 E0b。

## 3. 量化器感知的 canary 池（D 部分）

- **oracle 情形**（验证方知道攻击者用的量化器）：挑出"该量化器会翻转且最自信"的 K 个 context，在 20% 升级下 `p_q` 仍然等于 1，只需 N = 4–8。
- **迁移情形**（验证方猜错了量化器）：`p_q` 降到 0.3–0.9，N 在几十到几千之间。例如用 RTN 挑的池子去测 GPTQ 作弊者，升级 20% 时 N=714–2507。
- **局限**：池子里诚实失配的上界偏高（0.16–0.41），因为挑选时没有过滤参考 margin，池子混进了参考近似平局的位置。下一版应同时要求参考 margin ≥ 0.5。

## 4. 下一步

1. **E0b：强升级攻击者。** 攻击者用全精度模型离线生成标签，训练一个廉价的翻转预测器，特征可以是量化模型的 top-k logits、熵、注意力统计等。在 GPTQ 和更强的量化器上，测这个攻击者把被动 canary 逼到需要 N≥1000 要花多少重算成本。只有这个攻击能打穿被动方法，QFC 的引理 1（"量化模型完全看不出自己在被测"）才有用武之地。
2. **更大的模型和更强的量化器**（Qwen3-4B/8B，AWQ）。大模型的量化误差相对更小，`p_q` 会下降，被动方法的余量可能消失。
3. **重新定位 QFC。** 候选方向：
   - (a) 换威胁：例如作弊者用 8-bit 冒充 bf16 规格。这时被动方法 N≈4000，但 QFC 推导里的窗口也很窄，需要先验证植入能不能在 ρ≈0.5 下工作。
   - (b) 主打"对未知量化器的鲁棒性"：被动池的迁移性差（D 部分），而 QFC 的盒约束只依赖量化格点。
   - (c) 主打"抗翻转预测器"：前提是 E0b 证明这种攻击有效。
4. **论文现在就能用的部分**：
   - 被动 canary baseline，在真实 CUDA 和 Apple 跨硬件数据上；
   - "诚实漂移在 top-1 层面集中于平局"这个结论；
   - 升级攻击曲线。
   这三项都是 [C1] 没有的。

## 5. 数据纪律与已知问题

- 两种规格设定各自固定了诚实栈和作弊栈的划分，预注册判据按原定规则如实报告，没有改参数。
- Apple M4 节点上 HF 缓存里 mlx-community 8-bit 的 snapshot 不完整，改用 EXO 自己的模型目录 `~/.exo/models/mlx-community--Qwen3-0.6B-8bit`。它的 `model.safetensors` 的 sha256（3ad5c96e…）和 CUDA 服务器上 HF 缓存里的一致。
- CUDA 服务器上没有 matplotlib，升级曲线图没有生成，数据都在 `e0_escalation.csv` 里。
- GPTQ 是紧凑实现（无 act-order，非逐层顺序）。AWQ 没有覆盖。
- 区间挑选的 `p_h` 用的是诚实栈中最差者的 Wilson 上界。spec_8bit 的诚实栈包括 bnb-int8（失配 3.9%，三个 8-bit 实现里漂移最大），所以 N 是偏保守的。
