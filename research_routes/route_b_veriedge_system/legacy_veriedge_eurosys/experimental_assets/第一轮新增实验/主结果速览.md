## 论文主线

本轮实验不再把 VeriEdge 写成“一个固定 sparse-scalar TSTC verifier 解决所有异构验证问题”。更稳的主线是：

> heterogeneous edge LLM inference 中，一个 device/backend pair 是否能被低成本验证，本身就是 placement 约束。TSTC 是一个 tolerance-aware checkpoint-sketch chain 框架，scalar-coordinate、projected-token、projscalar1_abs 都是不同 sketch 实例。

核心文件：

- 主表：[tables/exp_e2_20260512_experiment_a_pair_family_projcos_paper_main_table.csv](tables/exp_e2_20260512_experiment_a_pair_family_projcos_paper_main_table.csv)

关键结果：

| Pair | Scalar16 FPR / TPR | ProjCos4 FPR / TPR | ProjCos8 FPR / TPR | ProjCos16 FPR / TPR |
|---|---:|---:|---:|---:|
| A/B | 0.150 / 1.000 | 0.020 / 1.000 | 0.080 / 1.000 | 0.120 / 1.000 |
| A/C | 0.110 / 1.000 | 0.045 / 1.000 | 0.075 / 1.000 | 0.135 / 1.000 |
| A/D | 0.090 / 1.000 | 0.020 / 1.000 | 0.065 / 1.000 | 0.065 / 1.000 |
| B/D | 0.245 / 1.000 | 0.075 / 1.000 | 0.075 / 1.000 | 0.065 / 1.000 |

解读：B/D 是 scalar-coordinate TSTC 的 hard pair。`projcos4` 将 B/D FPR 从 `0.245` 降到 `0.075`，同时 TPR 保持 `1.000`，说明 projected-token sketch 不是只在 A/B 上有效。

关键结论：

- `projcos4` 对 `gaussian`、`cross_prompt_stale_substitution`、`wrong_shard_output`、`layer_skip` 等方向/语义改变类攻击表现强。
- `projcos4` 对 `scale_perturbation` 失败，这是 cosine-only sketch 的预期边界。
- `same_prompt_old_run_replay` 是 negative control，不应混进 material TPR 主指标。

## D. Projected-token TSTC Overhead

核心文件：

- 主表：[tables/exp_e4_20260512_equal_budget_live_ab_main_table.csv](tables/exp_e4_20260512_equal_budget_live_ab_main_table.csv)
- 主图：[figures/exp_e4_20260512_equal_budget_live_ab_payload_latency.png](figures/exp_e4_20260512_equal_budget_live_ab_payload_latency.png)

关键结果：

| Variant | Reveal payload / trace | Hetero detect | Tamper detect | Hetero challenge latency |
|---|---:|---:|---:|---:|
| projscalar1_abs | 192 B | 0.030 | 1.000 | 3.709 ms |
| projcos4 | 768 B | 0.020 | 1.000 | 3.798 ms |
| projcos16 | 3072 B | 0.120 | 1.000 | 4.041 ms |
| scalar16 | 192 B | 0.150 | 1.000 | 3.603 ms |

解读：projected-token 增加了 sketch payload，但仍处于 challenge-time 可接受范围。不要写成 “free”，应写成 bounded overhead。

关键结论：

- E5 的目标不是证明 verification-aware policy 延迟最低。
- 正确结论是：risk-constrained / adaptive-verifier 能显著减少 infeasible/high-risk placement 与 false-dispute risk。
- 队列场景中 latency/goodput 可能不是全局最优，这是论文应诚实呈现的 tradeoff。

## 建议写进论文的边界

- TSTC 不是语义正确性的密码学证明，而是低开销 dispute evidence mechanism。
- `projcos4` 对方向改变类 tamper 强，但对 direction-preserving scale attack 有盲点。
- `projscalar1_abs` 对 scale/norm 更敏感，但 d=1 投影存在 projection-aware null-space attack 边界。
- placement 层的价值在于使用 measured verification profile 避免不可验证/高风险 pair，而不是让 verifier 单独解决所有问题。
