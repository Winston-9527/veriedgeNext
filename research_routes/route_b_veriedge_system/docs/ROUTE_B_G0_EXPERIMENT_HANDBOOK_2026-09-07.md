# 路线 B：G0 参考执行经济性实验手册

日期：2026-09-07。状态：待执行实验设计，不包含新测量结果。

本手册落实研究总账 WP0/G0 与学生手册 RB-G0-01。新增的实验编号、默认规模、成本边界和执行顺序是本次细化建议；不是已经实现的脚本接口或已有论文结论。科学主张仍以研究总账为准。

## 1. G0 要做出的决定

在预先声明的工作负载、信任假设和风险目标下，是否存在一种可实现的参考路径，使平均验证资源成本低于逐任务复制，并满足延迟、内存和披露约束？

G0 不验证部署级误报率或语义攻击检测率。它使用明确标记的条件检测率、升级率参数，或现有小样本几何结果做敏感性分析；G1 完成后必须回填实测值重算。G0 的 GO 只代表值得进入 G1，不是部署安全认证。

研究路线：

1. R-F：完整模型重放，作为成本与功能基线。
2. R-P：prefill 局部分片重放，第一条低复杂度候选。
3. R-D：decode 局部分片重放，重点审计 KV/cache 的来源、绑定和保留成本。
4. R-R：第二执行实例冗余分片，比较顺序、并发与资源占用。
5. R-T：可信参考服务；TEE 是需要具体硬件支持的单独子路线。
6. 对可行参考模式增加抽样、排队和批处理，检验成本与风险的交集。

## 2. 单机能做到什么

“单机可完成”指一台具备足够内存、能运行所选模型的主机，不等于当前机器已具备依赖或模型。CPU 可完成小模型功能实验；GPU/其他加速器不是逻辑正确性实验的必要条件，但决定性能是否具有部署代表性。当前仅确认本会话主机是 arm64；未完成内存、加速器、模型缓存和依赖清点，不能承诺当前主机可跑完所有模型配置。

能力标记：

- S：单机即可完成该实验的本地结论。
- S/P：单机可完成首轮筛选，部署性能或信任结论需要后续补测。
- H：需要特定硬件；普通单机只能做替代路径或参数分析。

| 实验 | 内容 | 单机判定 | 单机结论的范围 |
|---|---|---|---|
| E00 | 资产、硬件与目标冻结 | S | 明确本机可测项和缺口 |
| E01 | 完整执行/重放基线 | S | 本机参考成本；不代表远端速度 |
| E02 | prefill 局部重放 | S | 分片独立执行、输入绑定和本机成本 |
| E03 | decode 状态充分性及来源 | S | 状态依赖与绕过检查；不证明真实跨方非串谋 |
| E04 | 状态快照、保留与搬运 | S/P | 本机拷贝/存储实测；远端传输参数化 |
| E05 | 承诺、PACT 和本地时序 | S/P | 组件开销和逻辑顺序；不测真实公共信标/跨机 RTT |
| E06 | 冗余分片 | S/P | 顺序及本机竞争实测；不能推断两台设备并行延迟 |
| E07 | 可信服务与 TEE 可行性 | S/P；TEE 为 H | 本地服务测功能；TEE 必须真实硬件才能测 |
| E08 | 审计队列与批处理 | S/P | 单机服务时间和队列模型；集群调度另测 |
| E09 | 风险—成本可行区间 | S | 参数与本机实测支持的条件性结论 |
| E10 | 边界压力测试及决策 | S/P | 单机 Go/No-Go；多机未知项不能升级成已验证结论 |

单机多进程不能证明跨提供方独立信任；loopback 不能替代 WAN；同机两个模型实例不能替代跨硬件数值漂移；普通进程不能替代 TEE。缺少这些条件不阻止 G0，但相关结果必须是 CONDITIONAL_GO 或限定本机范围的结论。

## 3. 先冻结测量口径

### 3.1 执行单位与风险单位

分别报告：完整请求、一个 prefill 分片、一个 decode 分片步、一个明确长度的 decode 窗口。固定任务的输入长度、输出长度、受保护边界和重放范围。

单边界检测率不能直接标为全任务检测率。第一轮允许只研究一个受保护边界，但必须写清攻击范围。扩展多边界时，记录审计选择与攻击位置；不能无条件套用所有边界独立假设。

同步模式在裁决后交付；异步模式允许先交付再审计。二者分开报告响应延迟与发现延迟。异步发现无法撤销已经产生的损害，不得称为阻止单次有害输出。

### 3.2 比较口径

测原始执行 C_base 和新增验证成本 C_verify，报告：

- 新增成本比 C_verify / C_duplicate_extra。
- 总成本比 (C_base + C_verify) / (C_base + C_duplicate_extra)。
- 同等检查范围下 always-audit-local 与 sampled-local 的对照。

完整复制与局部审计的保证范围不同，不能仅给一条成本比而省略差异。同步双副本可能延迟低而总计算高，因此资源和延迟不能互换。

资源成本至少保留 accelerator-seconds/CPU-seconds（按设备分别列）、网络 bytes、峰值内存、保留 byte-seconds 和磁盘 bytes。需要汇总为货币或加权成本时预先给权重，并保留未加权原表。延迟单独按关键路径或离散事件模型计算，不能把所有并发组件耗时直接相加。

### 3.3 成本公式

按同一执行单位定义：

`E[C_verify] = C_always + p_a * E[C_ref + C_check | audited] + p_a * u * E[C_upgrade_extra | audited, upgrade]`

- C_always：实际输出/输入/状态的绑定，接收确认，审计决定前保留等所有任务必付成本。
- C_ref：被抽中后参考计算、参考状态获取与参考 root；不要把只在审计时产生的 root 计入所有任务。
- C_check：投影、回执、裁决、投影挑战等。
- u：被审计条件下升级概率，诚实和攻击分开。
- C_upgrade_extra：已经付出参考成本后的增量成本，避免完整重放重复计账。

若使用总体升级概率 p_upgrade，则直接乘 C_upgrade_extra，不再乘 p_a。clean/attack 比例加权后计算总体成本；攻击者诱发的高升级率也要单列压力场景。

### 3.4 预注册目标

在看可行曲线前写入 risk_targets.json：单次检测目标，或 m 次作弊至少发现一次的目标；成本节省目标、延迟上限、内存上限、发现时限和允许披露范围。

默认敏感性网格可用单次目标 {0.90,0.95,0.99}、持续作弊目标 {0.90,0.95,0.99}，以及新增成本相对复制上限 {0.25,0.50,0.75}。这些是设计扫描点，不是既有标准；必须另指定一个有场景依据的主目标。禁止跑完后只保留最容易达标的目标。

## 4. 共用测量规则与资产

### 4.1 已有资产及缺口

可复用：

- `experiments/pact_offline/pact_g16_protocol.py`、`pact_g16_state_machine.py`：本地协议与状态机。
- `experiments/pact_offline/results/conditional_power/`、`adaptive_gaussian/`：条件检测与 K 的初始敏感性输入，不是 G1 语义攻击测量。
- `shared/accountedge_runtime_and_captures/data/placement_workload.csv`：旧工作负载资产，需复核单位与来源。
- `shared/accountedge_runtime_and_captures/data_collection/collect_hf_verifier_profiles.py`：单机 HF 抓取起点。

已检查抓取脚本使用 `output_hidden_states=True, use_cache=False`，当前不能直接提供 decode 的 KV 状态快照或独立分片重放。其 synthetic/noise/profile 路径不构成真实异构校准。需要新增分片执行适配器、decode snapshot/restore、计时与资源记录，而非只给原脚本换参数。

旧目录只读复用；新脚本与结果全部写到 `experiments/reference_economics/`。本手册只设计这些脚本，不能假定它们已经存在。

### 4.2 最小工作负载

建议先选一个能在本机运行的开放小模型，记录模型与 tokenizer revision/hash、精度、后端、设备、层划分和 KV 格式。可优先评估已有脚本采用的 Qwen3-0.6B；若不兼容则选其他小模型并记录原因，不自动下载大模型。

- 功能 smoke：4 个独立 prompt，输入 32/128 tokens，decode 4 步。
- 主成本集：至少 12 个冻结 prompt，覆盖输入 32/128/512 tokens；decode 16/64 步；固定任务内容与 padding 规则。
- 初轮只选一个中间分片；通过后覆盖浅/中/深三个分片，记录具体层区间。C1/C2/C3 是边界标识，不等同于分片长度。
- K 的成本扫描：{8,32,64,256}；仅对仍有希望或需要定位的配置补 {512,1024}。大 K 不是 G0 自动停止条件，需看总成本。
- 主性能配置至少 5 次预热、30 次计时；冷启动另测。30 次结果的 P95 只作探索，若接近决策阈值则增加至至少 200 次并给区间/原样本。

模型长度限制或内存不足时标 UNSUPPORTED/OOM，不能替换成零耗时。先小规模筛选，再扩展，不跑所有维度的完整笛卡尔积。

### 4.3 计时纪律

固定 CPU 线程数、设备、电源模式和并发负载；记录温度/降频信息（可用时）。加速器计时前后使用后端同步，禁止只测异步 kernel 提交。功能正确性可先 CPU 跑通，性能结论只能归属于实测设备。

分开记录加载、预热、序列化、状态复制、传输、执行、投影和等待时间。计时路径避免额外抓取全模型所有 hidden states；需要抓取的开销通过开/关对照测出。深拷贝快照，不能保留会被后续 decode 原地修改的对象引用。

每个值标来源：`local_measured`、`legacy_measured`、`analytical`、`simulated` 或 `unknown`。缺值必须保留，禁止自动填 0。

## 5. E00：环境、资产与目标冻结

目的：确保后续“可运行”有证据。

步骤：
1. 记录 OS、CPU、内存、设备、可用磁盘、Python 和模型框架版本、模型缓存。
2. 检查上述代码/CSV/结果是否存在，记录 hash；检查是否能运行最小 PACT smoke。
3. 列出模型分层接口、KV cache 类型、是否支持序列化恢复、是否支持独立执行一段层。
4. 冻结主工作负载、主风险目标和成本目标。

输出：environment.json、asset_audit.csv、preregistration.json、missing_assets.md。

判定：模型不可用时仍可继续 E09 分析，但模型相关结论为 BLOCKED；写出最小解锁条件，例如“可离线加载某 revision 的模型并执行 4-token decode”，而非笼统“需要 GPU”。

单机：S。环境检查不证明后续性能。

## 6. E01：完整执行与完整重放基线

目的：确定分母，并建立真实参考。

步骤：
1. 同一冻结输入执行一次生产路径，记录 prefill、decode 分阶段耗时与资源。
2. 用第二次独立执行产生参考；固定 token 序列作 teacher-forced replay，测每一步相同上下文上的执行成本。
3. 另报告自由生成结果（如做），不要将采样导致的路径变化混入同输入参考比较。
4. 分别测模型常驻热重放和需要加载的冷重放；顺序两次运行，不假装有两台独立设备。
5. 保存目标边界 reference，作为 E02/E03 功能比较对象。

指标：C_base、C_duplicate_extra、prefill/decode 时间、加载成本、峰值内存、输出与边界摘要。

控制：相同模型、输入、精度和执行方式；禁用非必要 hooks 的性能基线单列。

结果：得到可重复基线则进入局部重放；OOM 或 API 不支持则减小 smoke 范围并明确限制，不凭旧论文数字替代。

单机：S。独立重跑是实现上的独立执行，不构成独立组织/硬件的信任证据。

## 7. E02：prefill 局部分片重放

目的：检验“只重放一个 shard”是否真能实现。

步骤：
1. 生产路径在分片入口保存完整输入 hidden state、position/mask、模型和层范围上下文。
2. 序列化、哈希；释放该次执行的中间对象，参考进程只接收明确列出的输入。
3. 参考进程仅执行目标层区间，不能隐式调用前缀层；用层调用日志确认。
4. 与 E01 同上下文的边界结果比较。功能容差事先记录；同栈浮点非确定性不应强行要求 bit 相等。
5. 分别测“状态已在本进程”“序列化后独立进程恢复”两条成本，后者作为可部署候选的本机近似。
6. 改动 mask、position、层范围或输入字节，检查上下文/root 不匹配是否被拒绝；重算 root 后形成另一输入的情况不得被解释为原输入正确性。

指标：局部计算、入口状态字节、序列化/恢复、状态绑定、相对完整重放成本、实际调用层数。

结果分支：
- 功能正确且成本低：R-P 保留，进入 E04/E05。
- 计算便宜但输入/状态搬运昂贵：条件保留，求允许搬运成本上限。
- 适配器暗中重跑前缀或读取生产方未声明内存：功能实验不通过，不能报告局部重放成功。
- 只支持 prefill：明确为 prefill-only 候选，不外推 decode。

单机：S；远端传输不在本实验结论内。

## 8. E03：decode 状态充分性、来源与绕过

目的：确认局部参考既能恢复，又没有把恶意状态当成可信起点。

步骤：
1. 在选定 decode 步保存该 shard 的入口激活、token history/position、mask、对应层 KV、cache position、模型版本；需要时保存采样/RNG 状态。
2. 对快照做独立拷贝和承诺，在新进程恢复，仅执行该分片下一步，比较 E01 的 teacher-forced 同步结果。
3. 逐项删除或错置 KV、position、mask、layer map，记录恢复失败、输出偏差或上下文拒绝。每种可篡改字段至少一个负例。
4. 测直接快照、从 token 前缀重建、从最近已验证检查点重建三种来源；不支持的来源记 UNKNOWN。
5. 专门运行“生产方恶意 KV”：生产方先提交一份被修改的 cache，再让参考使用同一 cache。若参考输出与生产方一致，不能把这个 PASS 算作验证了历史正确执行。
6. 为保留的模式说明可信状态锚点：从头独立重建、独立维护的参考 cache、已验证历史检查点或其他明确假设，并把代价计入。

指标：每步 KV 大小、完整快照/增量快照成本、重建前缀成本、恢复误差、检查点间隔与重建成本关系、绕过记录。

关键解释：哈希只绑定某份状态，不能证明该状态由正确历史生成。绑定完整性和历史真实性是两项不同要求。

结果分支：
- 有低成本且有可信来源的恢复路径：R-D 保留。
- 仅有“对生产方给定状态正确计算”的局部一致性：缩小保证，不能与验证完整 decode 历史的复制方案直接等价比较。
- 独立 cache 需要每步重复生产计算：按冗余路线计成本，不能称为便宜的抽样参考。
- 必须从头重建且与完整重放接近：decode 经济性 NO_GO，prefill 路线仍可独立继续。

单机：S。足以复现上述状态依赖；跨组织状态来源的真实性仍是部署假设。

## 9. E04：快照、保留与状态搬运

目的：防止低审计率掩盖所有任务都要付的状态保存成本。

步骤：
1. 测 no-audit baseline、仅 root、完整快照、增量快照四种路径。
2. 审计决定等待时间取本机测量值，并扫描 {1,10,100,1000} ms；这些扫描值是情景，不是网络实测。
3. 测反序列化、RAM copy、可用时 host/device copy、磁盘写读；共用同一序列化格式。
4. 对未审计任务在审计结果确定后释放；对被审计任务保留到证据完成/超时。测并发 {1,4,16} 的峰值与 byte-seconds，遇内存上限停止该配置。
5. 网络仅使用 `bytes / effective_bandwidth + protocol_rounds * RTT` 初步模型，带宽/RTT 明确标参数；分开列 source、destination 和排队，不能用 loopback 值当 WAN。

指标：C_always、每任务/并发峰值内存、保留 byte-seconds、状态大小随上下文增长曲线、允许带宽/RTT 范围。

结果：若降低 p_a 后固定保存成本仍占主导，抽样优势弱；若长上下文导致内存门槛，限制上下文或改状态方案；若结论取决于远端带宽则 CONDITIONAL_GO 并写最小所需带宽。

单机：本地部分 S，远端性能 S/P。

## 10. E05：承诺、PACT 组件成本与时序

目的：测定非参考开销，并确保没有为省成本改变安全时序。

本手册采用的 G0 待验证集成顺序：

`预提交策略 → 绑定实际输出及必要状态/接收确认 → 不可预测审计抽样 → 若被抽中，独立生成并绑定参考 → 产生新的投影 seed → 回执/裁决/升级`

审计抽样随机量和投影 seed 分域，不能直接复用已公开的审计随机量作为投影挑战。这样既允许未审计任务不计算参考，又保持实际/参考均在投影 seed 前固定。此顺序细化了旧文档中审计决定与参考承诺先后不一致之处，实施时应记录为版本化协议决策。

步骤：
1. 用 E02/E03 的真实张量测序列化、root、上下文检查、回执认证、投影和裁决，K 扫描沿用 §4。
2. 复用本地 G16 协议与状态机；只测已有 HMAC 时明确不是部署版公钥签名开销。
3. 比较分离处理与融合处理；未实现融合时只报分离实测，不把预期融合收益计入 GO。
4. 对未审计任务验证参考执行计数为 0；记录所有必要承诺/状态成本。
5. 测 late receipt、root 替换、任务重放、已知 seed、超时。超时必须 ABORT/升级，不能 PASS。
6. 本地随机服务只测顺序和成本；真实公共信标延迟/可用性放进 E09 参数表。

输出：component_times.csv、event_trace.jsonl、protocol_checks.json、bytes_breakdown.csv。

结果：若组件已很昂贵，先定位序列化/系数生成/状态保留，不直接增加模型规模。约 5% 非参考开销作为旧总账的诊断线，明确分母是任务执行还是边界处理；不能混用两者或视为自然定律。

单机：S/P。公开随机源安全性、网络分区、真实签名基础设施仍需后续验证。

## 11. E06：冗余分片对照

步骤：用相同任务与分片，在两个进程中分别执行。先顺序（资源成本），再同机并发（竞争与尾延迟）；仅在内存允许时双实例常驻。比较 always-on redundant 和 sampled redundant；将模型常驻内存与加载成本计入。

控制：两个进程不能共享生产方中间结果冒充独立参考。共享只读权重文件可作为部署配置，但必须说明。

指标：总 CPU/加速器时间、峰值内存、P95 延迟、并发 slowdown、冷启动。

结果：同机顺序可估算参考计算量；同机竞争严重不直接证明跨机冗余不可行。若复制单分片已很便宜，PACT 应同时对比该强基线，而不只对比完整模型复制。

单机：S/P；独立设备并行速度和资源调度需双机实测或标条件模拟。

## 12. E07：可信服务与 TEE 路线

普通可信参考：单机 client/server 独立进程接收已绑定状态并执行分片，记录序列化、请求处理、排队和返回成本；loopback 传输只作本地功能记录。

TEE 路线：先列所需平台、受保护内存、远程证明、模型/状态是否能在可信边界内运行、加速器是否属于该边界。具有具体支持平台时，才实测加载、证明、调用、分页/搬运。没有硬件时填 UNKNOWN，并由 E09 求“TEE 增量成本上限”；不在普通进程外包一层接口后称为 TEE 实测。

结果：可信服务可作为有明确组织信任假设的候选；TEE 缺硬件不是所有 G0 的阻塞，只阻塞 TEE 分支。若安全边界排除了主要计算，不能归入已验证的可信执行方案。

单机：本地服务 S/P；真实 TEE 为 H，可能一台支持主机足够，不意味着普通笔记本可完成。

## 13. E08：抽样参考的排队和批处理

目的：检查平均参考计算量下降后，尾延迟与保留内存是否反而失控。

步骤：
1. 从 E01/E02/E03/E06 取得逐任务服务时间样本，建立离散事件模拟器。
2. 分别测试稳定到达和突发到达；按服务能力归一化负载 {0.1,0.5,0.8,0.95,1.1}，不把超载伪装成稳定系统。
3. 扫 p_a，记录审计参考队列、完成时限、保留量；诚实/攻击升级率分别参数化。
4. 实际支持 batching 的模型适配器，实测 batch {1,2,4} 的耗时、padding 与内存；未测时不假设线性收益。
5. 以单机 worker 回放小规模队列，校验模拟器与真实本机事件记录是否一致。参考独占设备与共享生产设备分开建模。
6. 测批等待 {0,5,20} ms 的影响，并记录其仅为探索参数。

指标：平均/P95/P99 发现延迟、同步交付延迟、超时率、队列长度、参考利用率、peak retention。P99 仅在样本量/模拟运行长度充分时作为决策依据。

结果：批处理有效可保留；平均成本好但超时/内存失控则缩小负载区间；攻击诱导升级导致队列崩溃则需要容量/限流与明确失败语义，不能把丢弃审计记为成功通过。

单机：S/P；集群规模化结果是模拟，G2 需补跨主机实测。

## 14. E09：风险—成本联合扫描

### 14.1 风险语义

令 d 为被审计条件下实际发现作弊的概率。不能把 INCONCLUSIVE 自动视作已检测；若计入升级，需建模升级成功率、时限和成本。G0 可将它们设为显式参数，待 G1/G2 替换。

同一执行单位、固定 d 且审计独立时：

`D_single = p_a * d`

`D_m = 1 - (1 - p_a*d)^m`

若目标为 D_single ≥ r，则 `p_a ≥ r/d`；若 r>d 则连全审计也不能满足。

若目标为 D_m ≥ r，则 `p_a ≥ (1-(1-r)^(1/m))/d`。

审计/攻击有相关性、提供方能预测抽样、边界选择覆盖不足时，上式不能作为保证；单列压力模型。系统未在伤害发生前阻断时，“被发现”不能等于“伤害被避免”。没有 harm 数据时只画给定 H 的参数曲线，不产生伪实测危害数。

### 14.2 扫描输入

- p_a：{0,.001,.002,.005,.01,.02,.05,.1,.2,.5,1}，另计算解析交界点。
- m：{1,5,10,50,100}。
- d：优先使用来源清楚的条件结果，额外扫描 {0.5,0.9,0.95,0.99,1.0}；明确不是语义检测保证。
- u_honest/u_attack：分别扫描 {0,.01,.1,.5,1}，只扩展有希望的候选。
- 单边界与多边界保护配置分开；现有 rho {.01,.02,.05} 只代表数值 baseline。
- 所有保留参考模式；普通/高价值任务；同步/异步；本机实测与远端情景分开。

### 14.3 判定方法

求风险要求的 p_min，成本、时限、内存可接受的 p 集合，取交集。简化单调平均成本模型下可求 p_max；复杂排队与批处理不假设可行集合一定是连续区间。

对 unknown 成本反求上限，例如“状态搬运小于 X ms 且信标等待小于 Y ms 才可行”。X/Y 必须由本次输入算出，本手册不预填结果。

使用服务时间区间/保守值、检测率下界和较高升级率做鲁棒性扫描；只在一个乐观点上可行应标 CONDITIONAL_GO。

### 14.4 最低模型自检

- p_a=0：主动检测为 0，参考计算为 0，但 C_always 不自动为 0。
- p_a=1,d=1：单次检测为 1；V2 与全审计覆盖一致。
- 固定其他参数时 d/m/p_a 增大，解析累计发现概率不下降。
- 抽样参考需求随 p_a 增大不下降；批处理可能改变每次平均成本，不要求所有实测总延迟严格单调。
- u 条件概率/总体概率两种记法得到同一成本。
- p_a=0 时没有审计内升级；独立触发的强升级另设模式。
- missing value 不变成零；不可行概率不裁剪成“达标”。
- 复制基线与候选的模型、工作单位和保证差异都有记录。

输出：risk_curves.csv、cost_grid.csv、feasible_regions.csv、sensitivity.csv、cost_risk_frontier 图、go_nogo_summary.json。

单机：S。可完成数学扫描，结论可靠度受输入证据限制。

## 15. E10：最终压力场景与决定

对最有希望的 1–2 个模式运行以下压力配置：长上下文、大保留窗口、冷参考、突发负载、高升级率、d 下界、较差带宽/RTT。明确哪些是本机实测、哪些是情景。

| 可能结果 | 研究解释 | 决策/下一步 |
|---|---|---|
| prefill 局部参考便宜，风险成本交集稳健 | 有一个可实现的局部部署场景 | GO，进入 G1；不同时声称 decode 成立 |
| decode 需要可信 cache，但维护它几乎等价于复制 | 抽样节省被历史状态成本抵消 | decode NO_GO，保留 prefill 或冗余场景 |
| 单次高检测目标迫使 p_a≈1 | 抽样无法提供廉价单次保护 | 仅在有依据的持续作弊审计场景评估；不能事后偷换主目标 |
| 参考便宜，但所有任务保留/承诺昂贵 | 问题在固定数据路径成本 | 改数据路径后重测 E04/E05 |
| 成本优势依赖某网络/TEE 参数上限 | 缺少关键部署测量 | CONDITIONAL_GO，给出补测参数和通过上限 |
| 多数任务预计升级，候选不优于直接重放 | PACT 成为前置额外成本 | 改策略/机制或 NO_GO |
| 只有不现实的 d=1,u=0 才成立 | 对 G1 结果缺乏容错空间 | 不给稳健 GO，先最小 G1 验证 |
| 没有可运行模型/状态接口 | 没有充分证据 | BLOCKED，列最小解锁实验 |

GO 还须写清披露约束：若参考需要将受限 prompt、激活或 KV 交给不允许的主体，即使成本低，也不是该部署场景的可行模式。

## 17. 推荐执行顺序与停止规则

第一轮 5 个工作日是原工单的粗估，前提是模型和接口可用；下面是优先级安排，不承诺五天完成所有实验：

1. E00 + E09 解析下界：若主单次风险目标已迫使全审计，尽早识别。
2. E01 + E02：建立完整分母和最小 prefill 局部候选。
3. E03：尽早排查 decode 状态来源，避免最后才发现必须全程复制。
4. E04 + E05：加入所有任务固定成本和真实协议成本。
5. E09 初次决策：没有交集则停止扩展；有条件交集则仅补关键缺口。
6. 有希望的模式再做 E06/E08；E07 只有场景允许且资源可用时推进。
7. E10 + 总 memo；进入 G1 后用新的条件检测、升级率和区间回填 E09。

第一轮最低完整交付是：一个真实完整重放基线、一个真实局部候选（或其不可行证据）、decode 状态来源审计、承诺/保留成本、风险成本扫描和明确决策。无需先实现完整三节点 VeriEdge，也无需把所有参考路线都开发成生产系统。
