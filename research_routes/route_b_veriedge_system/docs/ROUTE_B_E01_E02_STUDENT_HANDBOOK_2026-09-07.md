# E01 最小基线＋E02 完整实验：Prefill 局部参考执行

日期：2026-09-07。状态：学生实验手册，待执行；不包含新增实验结果。

本版替代此前 E02 学生任务书的实验安排。与 G0 总手册的关系是：缩减 E01 为同栈 prefill 基线，完整保留 E02 的六项要求，不扩展 decode 或完整 PACT 实现。

## 1. 研究问题与结论边界

独立参考执行若必须重新运行整个模型，验证成本可能很高。本实验检验：

> 保存目标分片的入口 activation 与必要上下文后，能否在新的执行进程中只重放该分片，产生与完整执行一致的边界输出？计入保存、绑定和恢复成本后，是否仍比完整重放便宜？

需要分别回答三个问题：

1. 功能：局部执行是否正确复现目标分片？
2. 输入完整性：重放是否使用指定的输入和上下文，修改是否会被检查拒绝？
3. 成本：省去的计算是否大于新增状态处理成本？

局部重放验证的是“对给定入口输入执行这一分片”。它不自动验证入口 activation 的上游来源正确，也不证明整个模型正确。这里的参考进程可以对应未来参考节点，但单机进程隔离不等于跨提供方非串谋。

## 2. 研究范围

- 一个单机可运行的小型语言模型，一种精度、后端和设备配置。
- 只做 prefill，固定输入，不进行自由生成或 decode/KV 历史恢复。
- 目标分片为连续层区间；至少一个区间必须位于模型内部，确保确实省略了前缀计算。
- 采用完整张量比较作功能检查，不要求实现 PACT 随机投影、异构校准或攻击检测率评测。
- 所有实验可在一台满足模型资源要求的机器上完成。CPU 可做小模型功能实验；成本结论仅属于实测设备。

可优先考虑项目现有脚本使用的 Qwen/Qwen3-0.6B；若更换，说明兼容性、资源与选择依据。不要把获得新硬件作为开始实验的默认前提。

## 5. T1：E01 最小完整重放基线

### 要解决的问题

得到目标分片输出的功能参照和完整重放的真实成本，避免用估计值作分母。

### 实验要求

1. 冻结输入及执行配置，运行一次完整 prefill，保存选定分片入口和出口的结果及元数据。
2. 从相同输入独立运行第二次完整 prefill；不得直接复用第一次的中间结果作为第二次的结果。
3. 比较两次执行的目标边界输出，记录同栈重复执行误差。用开发输入确定功能容差并冻结，然后应用于主实验输入。
4. 测常驻模型的完整重放耗时；分别记录进程启动/模型加载与执行，不把冷启动和热执行混合平均。
5. 性能基线关闭非必要抓取；需要抓取边界的生产路径另测增量开销，不能把昂贵抓取加在完整基线上、却从局部路径里删去。

第二次执行至少有一次在新进程中完成，用于检验配置可恢复。常驻成本可在该参考进程内预热后重复测量，不要求每次计时都重新加载模型。

### 5.1 输出比较：比较 activation，不比较生成 token

两次完整 prefill 在同一目标边界得到张量 A、B，A 为第一次执行，B 为第二次独立执行。应先核对输入 token IDs、模型配置、边界定义、shape/dtype 和有效 token mask。只在对齐的有效位置比较，padding 不计入；先检查 NaN/Inf，出现非有限值时标 INVALID，不继续给“通过”结论。

设有效元素数为 N，将对应元素展平为 a_i、b_i，差值为 e_i=b_i-a_i。比较前转成 float64 进行离线误差计算，不改变模型实际执行精度。必须报告：

| 指标 | 定义 | 用途 |
|---|---|---|
| RMSE | sqrt(sum(e_i²)/N) | 整体平均误差幅度，activation 数值单位 |
| relative L2 | sqrt(sum(e_i²))/sqrt(sum(a_i²)) | 相对误差，无量纲，便于不同幅值比较 |
| max absolute error | max(abs(e_i)) | 防止少量大误差被平均掩盖 |
| violation fraction | count(abs(e_i)>atol+rtol*abs(a_i))/N | 超过冻结容差的元素比例 |

relative L2 的分母为零时：A、B 均为零则记 0；否则记正无穷并单独标记，不能随意加 epsilon 掩盖。可额外报告 cosine similarity，但它不能替代上述指标，也不能单独作为通过依据；成比例缩放仍可能有很高 cosine。

功能通过定义：输入/上下文/shape/dtype 一致、元素有限，且 violation fraction=0。atol/rtol 根据模型精度、同栈开发运行及所用算子的依据，在正式测试前写入配置并冻结；本手册不凭空规定适用于所有后端的数值。不能只让两次完整执行互相接近，就证明模型语义正确；该判据只用于本实验的重放一致性。

token 一致性不是 T1 指标：本实验不做 decode，也不通过生成文本检验中间分片。T3 的 FULL/L0、FULL/L1 及 L0/L1 比较沿用本节指标与同一冻结判据。

### 5.2 开销定义：主指标是完成时间，另报内存和字节

本节“捕获开销”指开启目标边界捕获后，完成相同 prefill 工作额外增加的实测时间。单位 ms 和百分比；不是理论 FLOPs，也不称为“计算量增加百分比”。捕获可能只增加复制、同步和内存保留，即使模型算术量不变也会变慢。FLOPs、能耗不作为本任务必交指标；如额外测量须独立说明工具与口径。

定义两种配对模式：

- CLEAN：普通完整 prefill，不安装目标抓取器，不保留全层 hidden states，不在计时区间比较输出或写文件。
- CAPTURE：与 CLEAN 相同的模型、输入和执行终点，只增加目标分片入口/出口及必要上下文的捕获。禁止为方便启用额外的全层捕获。

两种模式均预先准备相同输入，常驻权重。开始计时前等待设备前序工作完成；从调用 prefill 前到所需操作完成并同步后，记录墙钟耗时。排除 tokenization、模型加载、离线误差比较、绘图及结果文件写入。

CAPTURE 结束时必须已持有不再依赖原临时对象的有效快照。明确快照位于 CPU 还是设备内存；若实现要求 clone 或 device-to-host copy，必须计入。不要只记录 hook 注册或异步提交时间。序列化、哈希、磁盘保存成本归 T2/T5 单独测量，不混入此处 Δcapture；计入最终 L1 成本时不能遗漏。

对每个输入、目标分片与 repeat_id，配对测 CLEAN 和 CAPTURE，交替或随机化顺序并记录；保持预热、线程、精度等相同。正式计时至少 30 对/配置，离散情况明显时增加；冷启动另表，不纳入热执行平均。功能数据抓取和 CLEAN 计时使用不同运行，不可能同时“没有捕获”又从该次运行导出中间张量。

按配置计算：

`delta_capture_ms = mean(t_capture_ms - t_clean_ms)`

`capture_overhead_pct = 100 * delta_capture_ms / mean(t_clean_ms)`

原始执行基线 C_base 为匹配配置 CLEAN 的平均热执行 ms；C_full 为第二次独立完整重放的平均热执行 ms，不能直接复制 C_base 作为测量值。若完整参考需要出口捕获，另报其明确范围下的增量，并在后续对比中计入；本节入口+出口捕获与仅出口捕获不能混称同一项。

报告配对时间差的 95% 区间，可用以配对记录为单位的 bootstrap（固定 seed 并记录方法）。平均差为负或区间跨零时保留原值，说明尚不能分辨捕获开销，不裁剪成零，不声称捕获使计算加速。

内存和数据另报：输入快照 bytes、出口快照 bytes、上下文 bytes、host peak RSS、device peak allocated bytes（适用且工具可用时）。说明工具、测量范围及 reset 方法；峰值测量可单独运行以免 profiler 扰动主计时。工具无法提供时记 NA 及原因；主机和设备内存不直接相加，预留内存不冒充实际已分配内存。

## 6. T2：确定、保存并绑定分片输入

### 要解决的问题

参考执行需要哪些信息？如何确认它收到的是指定的那份信息？

### 实验要求

1. 在分片入口取得完整 hidden state，以及该模型需要的位置、mask 等执行信息；明确模型和层范围上下文。
2. 设计可序列化的输入包，并给出字段清单、shape/dtype、来源和用途。由模型实现确认充分性，不将某一张量误当成全部输入。
3. 定义确定的内容及上下文绑定方式。记录 schema、模型标识、层范围等如何进入 root 或受核对的预期上下文。
4. 将输入包交给参考路径，释放原执行中相关临时对象。恢复过程不得依赖隐式全局变量或可变共享对象。
5. 记录输入 tensor、上下文、序列化包的大小，以及保存、序列化和绑定成本。

预期 root/上下文应来自单独保存的实验任务记录，而不是完全相信输入包自报的 root。否则同时替换输入与其自报哈希不会受到约束。这里仅要求本地固定任务记录，不要求签名、区块链或完整协议。

### 交付

input_schema.md、样例输入包、独立任务记录、输入大小与准备成本表。

### 判定

输入依赖仍缺失时保留失败记录并补充清单。root 一致只证明与指定包一致，不证明原输入由正确上游生成。

## 7. T3：两条局部重放路径与正确性

### 路径 L0：状态已在本进程

使用已经准备好的入口状态，仅执行目标层区间。该路径观察局部计算本身，不含独立交付输入的全部成本。

### 路径 L1：序列化后独立进程恢复

在新进程中读取输入包、核对任务记录、恢复执行所需状态，并仅运行目标层区间。允许加载明确声明的权重和配置；不允许读取原运行的其他隐式状态或目标输出来生成结果。

目标输出文件可以由外部比较程序读取，但不能作为参考执行的计算输入。分开保存重放入口和比较入口，便于检查数据依赖。

### 两条路径共同要求

1. 使用与 T1 对应的输入和上下文，比较分片出口完整张量；记录形状和事先选定的误差指标/阈值。
2. 提交实际层调用日志，确认没有前缀层或整个模型调用；不能仅凭函数名称判断。
3. 比较 L0、L1 与 T1 的输出，定位恢复前后是否出现额外误差。
4. 至少给出一条从已保存输入包开始、在新进程产生局部输出的可复现命令。

### 可能结果

| 结果 | 应如何解释 |
|---|---|
| L0/L1 都与完整执行一致 | 支持该配置下的独立局部恢复 |
| L0 正常、L1 不一致 | 优先调查序列化、配置与恢复依赖 |
| 两条都不一致 | 调查分片边界、接口和基线，不立即归因于数值漂移 |
| 结果一致但实际重跑前缀 | 不满足局部重放要求 |

本任务没有自动允许的统一误差阈值；阈值需有依据且在正式比较前冻结。不得为掩盖接口错误不断放宽容差。

## 8. T4：输入与上下文绑定对照

### 要解决的问题

独立恢复是否会错误接受被替换的输入或执行上下文？

保持任务记录固定，分别修改输入字节、位置相关字段、mask 与层范围。某字段不存在时，记录模型依据并选择语义相当的执行字段，不无理由跳过。

| 用例 | 条件 | 预期检查行为 |
|---|---|---|
| B0 | 原始输入包与原始任务记录 | 正常恢复并运行 |
| B1 | 输入内容变化，保留旧 root | 完整性检查拒绝 |
| B2 | position 或 mask 变化 | root 或预期上下文不一致时拒绝 |
| B3 | 层范围或模型上下文变化 | 与指定任务不一致时拒绝 |
| B4 | 修改内容并生成新 root，仍使用原任务记录 | 不能替代原任务的输入包，应拒绝 |
| B5 | 修改内容和 root，并显式建立另一份任务记录 | 可以成为另一个任务；不能证明原输入正确或原任务通过 |

记录修改字段、预期行为、实际行为、拒绝原因、是否执行了目标层。完整性对照应在重放前核对；不能把后续张量误差碰巧变大当成哈希检查成功。

B5 不要求输出必然改变：某个改动可能对该输入没有影响。它检验的是解释边界，而非强行制造数值差异。

交付 binding_cases.csv 与可重复执行的对照入口。遇到本应拒绝却接受的结果，修复后保留原始失败记录。

## 9. T5：成本测量与比较

### 9.1 必报项目

| 项目 | 需要记录什么 |
|---|---|
| 完整重放 | T1 的热执行、加载及捕获增量开销 |
| L0 | 分片计算、实际层数 |
| L1 准备 | 捕获/复制、序列化、绑定、包大小 |
| L1 恢复 | 读取、解析、完整性检查、设备搬运（如有） |
| L1 计算 | 目标层计算、权重加载单列 |
| 资源 | 输入字节、可测峰值内存、逐次耗时 |

把操作归入互斥项目，避免一次 copy 或哈希重复计账。磁盘交付、内存交付等使用的介质要写清；本机磁盘耗时不代表未来网络耗时。

### 9.2 比较方式

至少报告三个成本数：

`C_L0 = 本地状态已准备好时的分片计算成本`

`C_L1_warm = 必要输入准备/绑定 + 独立恢复/检查 + 分片计算`

`C_L1_cold = C_L1_warm + 实际发生的进程启动及模型加载等冷成本`

热恢复测量需在独立参考进程内加载并预热，然后处理正式输入包；L1 的“新进程可恢复”与“每个样本都冷启动”是不同要求。

分别与匹配热/冷假设的 C_full 比较，报告绝对值及比值。若只加载了部分权重，记录实际加载范围；若加载全模型，也应如实计入内存及冷启动。

完整重放比局部重放检查范围更广，因此除完整分母外，**建议**补测“从 prompt 重放到目标出口”的前缀基线，以区分省去前缀与省去目标之后的后缀所带来的收益。该项不是原 E02 硬要求；未做时必须说明范围差异，不声称等价保证下的全部收益。

将所有任务都要准备输入的成本单列，未来审计概率降低时不能把这部分自动降为零。本实验不模拟审计概率，也不测长时间保留与多机网络；交由后续 G0 实验。

### 9.3 最小矩阵与测量纪律

先用一个输入、一个分片通过 T1–T4，再扩大。主测量建议至少四个不同输入，覆盖两个输入长度范围；选择两个不同层区间，其中至少一个为中间分片。具体值由学生说明理由，不强制完整笛卡尔积。

这是本任务的起步规模，不是 G0 原文的统计门槛。若只完成更小范围，明确结论的限制，并解释资源或接口原因。

预热次数、重复次数、运行顺序和统计摘要由学生在方案中确定；需保留逐次测量并解释波动。不得只测一次或只取最快值。接近“是否有收益”的分界时增加测量，若仍不能区分则报告不确定。

固定线程/设备/后端等影响因素；异步设备需确认计算已完成。所有配置采用一致计时口径，不混用有抓取与无抓取、有加载与无加载结果。

至少给出一张分项成本图和一张配置比较表；图表必须能回到原始记录。

## 10. 可选演示：实际输出被改动时的参考差异

T1–T5 完成后，可以保持入口输入不变，显式改变生产路径的一个出口值或计算结果，再与独立参考输出比较。

该演示说明参考如何提供差异证据。它不是 E02 必要项，不替代 T4，也不使用“PACT 检测率”“恶意行为普遍可检测”等表述。入口被上游改变但双方都使用同一新输入时，不要求局部参考发现上游错误。

## 11. 结果解释与下一步

| 实验结果 | 可得结论 | 下一步 |
|---|---|---|
| 功能正确、绑定有效、含恢复仍便宜 | prefill 局部参考是可继续的本机候选 | 将分项成本交给 G0 E04/E05 |
| L0 很快、L1 优势消失 | 准备或恢复抵消计算节省 | 指明瓶颈及一个最小后续实验 |
| 某些配置便宜、其他配置不便宜 | 收益依赖配置 | 报告范围，不只保留好结果 |
| 结果一致但执行范围/隔离不满足 | 尚未实现所要求的局部参考 | 修正适配器或报告接口阻塞 |
| 功能或数值差异原因未定位 | 暂不能评价经济性 | 缩小样例定位，不用成本图掩盖 |
| 被修改输入在旧任务下被接受 | 状态绑定实现存在缺口 | 修复并保留回归对照 |

“没有收益”是有效结果，不因加速比低扣减实验质量；但缺少独立恢复、完整计账或可复查记录不是负结果，而是实验尚未完成。

## 13. 三个检查点与验收

1. **方案检查**：模型能运行；边界和计账方案明确；提交待确认事项。
2. **功能检查**：T1–T4 在最小样例完成，展示新进程恢复、层日志及绑定对照，再扩大成本测量。
3. **结果检查**：T5 原始数据、两条路径成本、完整报告与结论边界。

最低验收清单：

- [ ] 两次完整 prefill 真实执行，成本基线可追溯。
- [ ] 入口 hidden state 与所需上下文明确、可序列化、可绑定。
- [ ] L0 与 L1 均实现，L1 能脱离原进程恢复。
- [ ] 层调用证据证明只执行目标区间。
- [ ] 与 E01 同上下文出口比较，容差事先确定。
- [ ] 原输入、内容修改、上下文修改、新 root 对照均有记录。
- [ ] 局部计算、准备/绑定、恢复、加载和字节数分别报告。
- [ ] 成本分母、热冷假设和验证范围差异写清。
- [ ] 失败与无收益配置保留，别人可复现主要结果。
- [ ] 不把局部一致性、单机成本或演示差异扩大成安全保证。

遇到阻塞时提交最小复现、已尝试方法和精确问题。实现接口与实验参数属于探索内容，可以讨论，但不能为保持进度绕过独立恢复或完整计账要求。
